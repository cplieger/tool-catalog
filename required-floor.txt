# Engine-floor tool names every published catalog MUST resolve, verified by
# `toolcatalog verify` before a release is cut.
#
# This is the floor for a GENERAL catalog: the tools the toolbelt engine itself
# adopts as backends for its own source kinds, plus the one engine seed template
# a registry carries. Nothing here is a product's choice -- every name resolves
# from mise/aqua registry data alone.
#
#   npm:   -> node   (mise core:node, translated to aqua:nodejs/node)
#   go:    -> go     (mise core:go, translated to aqua:golang/go)
#   pip:   -> uv     (its own aqua registry entry)
#
# cargo: -> rust is deliberately ABSENT. aqua packages `rustup-init`, not a
# toolchain, so a translated entry would land with no `cargo` on PATH; a
# consumer that wants cargo: sources bundles a rust entry of its own.
#
# Of the DefaultSeed templates (gopls, typescript-language-server, pyright,
# rust-analyzer), only rust-analyzer is in a registry. The other three are
# curation and belong to whichever product seeds them; each consumer verifies
# its own bundled tools at image build with `verify -overlay`. No forge CLI is
# listed: the engine neither seeds nor runs one, so a product that needs gh
# names it in its own required set.
#
# backend runtimes (auto-adopted dependencies)
go
node
uv
# the DefaultSeed template a registry carries
rust-analyzer
